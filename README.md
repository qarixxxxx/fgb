# Паспорта систем · Технекон

Локальное приложение для комплектации, производства, калибровки и экспорта паспортов.

## Запуск

Нужен установленный Python 3.10 или новее (рекомендуется 3.12+). При первом запуске нужен интернет для установки зависимостей. После установки PDF и все графики работают без интернета; Microsoft Word и LibreOffice не требуются.

- **macOS:** откройте папку проекта в Терминале и выполните `python3 start.py`. Также приложен файл `Запуск-macOS.command`.
- **Windows:** запустите `Запуск-Windows.cmd` или выполните в папке проекта `py -3 start.py` (при отсутствии `py` — `python start.py`).

Браузер откроется по адресу http://127.0.0.1:8000/app/index.html. Сервер работает, пока открыто окно запуска. Для остановки нажмите Ctrl+C. Если порт занят, можно задать переменную окружения `PASPORT_PORT`, например `8001`.

Если приложение уже запущено из старой папки, сначала остановите его и запустите новую версию из этой папки. Не открывайте HTML-файлы напрямую: интерфейс обслуживается сервером.

## Паспорт PDF

1. Откройте проект.
2. В блоке «Паспорт изделия» заполните **наименование системы**, **заказной номер системы** и **шифр паспорта**. Это отдельные реквизиты: они не подменяются кодом проекта или серийным номером контроллера.
3. Нажмите «Сохранить и скачать PDF». Кнопки «Паспорт PDF» в списке проектов и в поверке используют сохранённые реквизиты.

Титул A4 содержит исходный фирменный фон на всю страницу (210 × 297 мм) с текстом поверх. Кириллические шрифты встроены в PDF. Печать без белой рамки на бумаге зависит от поддержки печати без полей вашим принтером; в самом PDF фон не имеет полей.

В PDF включены сведения о системе, комплектность всех контроллеров, спецификации РД и КД, сохранённые протоколы калибровки с графиком и сведения о поверке. Пустые данные обозначаются прочерком.

## Калибровка

Откройте **Производство → Калибровка**. Доступны три начальных шаблона:

| Параметр | Единица | Начальный диапазон |
| --- | --- | --- |
| Виброскорость | мм/с | 0–25 |
| Виброускорение | м/с² | 0–100 |
| Виброперемещение | мкм | 0–1000 |

Диапазоны — редактируемые заготовки, не утверждённые метрологические характеристики. Для каждого протокола выберите систему в целом или конкретный активный канал, задайте диапазон, частоту и оборудование. Оператор вводит допуск по применяемой методике; по умолчанию он не задан.

- Точки создаются на 0, 25, 50, 75 и 100% диапазона. Кнопка «Сформировать 5 точек диапазона» пересоздаёт их после изменения границ; при наличии измерений запрашивается подтверждение очистки.
- Можно редактировать эталонные значения, добавлять и удалять точки (от 2 до 50).
- Измерения «до» и «после» изначально пустые. Поддерживаются десятичная точка и запятая, включая отрицательные числа.
- Графики показаний и отклонений обновляются при вводе. Наведите указатель на точку для просмотра значений.
- **Отклонение, % диапазона = (измерение − эталон) / (верхняя граница − нижняя граница) × 100.** Формула определена и в нулевой точке. Это приведённое отклонение, а не относительная погрешность от эталонного значения.
- Оценка «в пределах допуска» появляется только при заданном допуске и заполненных корректных измерениях «после» во всех точках.
- Нажмите «Сохранить протокол». В паспорт входит последняя сохранённая редакция. Несохранённые изменения защищены предупреждением при уходе. Одновременная перезапись из другого окна отклоняется.

## Данные и обновление

База: `data/pasport.db`. В этой поставке сохранена копия исходной базы. Проверочные измерения в неё не добавлялись. Исходная папка в Downloads не изменялась.

Новые таблицы `passport_settings` и `calibrations` создаются автоматически при запуске. Имеющиеся таблицы и проекты не перезаписываются. Перед переносом более новой рабочей базы остановите оба приложения, сохраните резервную копию и замените `data/pasport.db` в новой папке на вашу актуальную базу. Не копируйте старые папки `.venv` между системами: новая версия создаёт своё окружение `.venv-portable`.

## Проверка

Для разработчика из папки `backend`:

```text
python -m pip install -r requirements-test.txt
python -m pytest tests -q
```

Проверены 16 автоматических сценариев: PDF с кириллицей и фоном на весь лист, длинные таблицы, сохранение протоколов, валидация, разграничение проектов, конфликт редакций и удаление, создание окружения с пробелами в пути и восстановление отсутствующего pip. Ручная проверка выполнена на macOS в браузере: ввод с запятой, построение графиков, сохранение и восстановление данных. Добавлена конфигурация GitHub Actions для macOS, Windows и Linux; запуск на Windows в рамках этой работы не выполнялся.

Для независимой тестовой базы можно задать переменную `PASPORT_DB_PATH` с полным путём к файлу.

## Изменения

- Автоматическое восстановление pip при неполном создании окружения.
- Прямая генерация PDF вместо DOCX; собственные шрифты и переносимые пути.
- Отдельные заказной номер и шифр на полноформатном титуле.
- Таблицы и графики калибровки, сохранение протоколов и включение в PDF.
- Единый деловой стиль, адаптивная навигация, улучшенные формы и состояния сохранения.
- Убран жёсткий адрес API; Chart.js поставляется локально.
- Исправлены проверка канала ОТК в рамках проекта, проверка пустого/повторного кода проекта и очистка связанных записей при удалении проекта.

Встроенные шрифты DejaVu распространяются с лицензией в `backend/app/fonts/LICENSE_DEJAVU`. Chart.js — MIT, лицензия в `frontend/vendor/LICENSE-Chart.js.md`.
